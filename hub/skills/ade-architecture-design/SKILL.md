# 架構設計

共同原則見[架構工作](kb:process/607817)，各階段的規則見[架構設計的規則](kb:process/e66b14)，步驟中引用的分析方法列在兩者的導覽中。本 skill 只寫執行步驟，不重述規則。

每個步驟完成後摘要產出，用 `AskUserQuestion` 請使用者確認或修改，確認後才進入下一步。使用者要求跳過某一步時，說明跳過的代價再照做，例如跳過品質屬性會讓風險評估缺乏依據。

0. **判斷範圍**：使用者只要單項產出時，讀[架構工作](kb:process/607817)與對應的分析方法，只執行該項，不展開整個流程。
1. **讀規則**：讀[架構工作](kb:process/607817)與[架構設計的規則](kb:process/e66b14)。
2. **盤點輸入**：依規則的「輸入」確認手上的資料，缺少必要輸入時暫停並請使用者提供。改造既有系統時，讀[現有架構盤點](kb:process/999284)，交給 subagent 依方法重建現況，只取回產出。
3. **情境分析**：依「設計簡報」寫出設計簡報，請使用者特別確認假設清單。
4. **品質屬性**：讀[品質屬性分析](kb:process/8796e4)，產出驅動屬性、場景與 utility tree，請使用者確認排序與度量值。
5. **候選方案**：依「候選方案」產生 2 到 3 個結構不同的方案，請使用者確認候選是否涵蓋他們想探索的方向。
6. **評選**：依「評選」逐一以高優先場景檢驗候選方案，給出推薦。由使用者選定方案。
7. **細化**：依「細化」產出架構圖、技術清單、關鍵流程與資料概觀，所需的方法依規則引用的知識閱讀。單向門的技術選型建議另外執行 `ade-tech-decision`。
8. **風險閉環**：讀[架構風險評估](kb:process/d923ae)，以 L2 為畫布評估。等級為高的風險全部閉環前不進入下一步；緩解改動架構時回到步驟 7 更新架構圖。
9. **記錄決策**：依「交付」列出需要 ADR 的決策，逐一依 `ade-create-adr` 撰寫。
10. **產出文件**：以本 skill 目錄的 `template.md` 撰寫架構設計文件，存放位置詢問使用者；組織有既定範本時改用該範本。依「交付」逐項自檢，未通過的項目補完或向使用者標明。
